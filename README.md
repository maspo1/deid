# deid
<p align="left">
  <img src="./assets/icon/app.ico" alt="프로그램 로고" width="100">
</p>

**파일 속 개인정보와 민감정보를 찾아 비식별화하는 오프라인 도구**

`deid`는 폴더 안의 파일을 검사해 개인정보와 민감정보를 치환하고, 이미지에서 발견한 정보는 흐림 처리합니다. 파일 내용뿐 아니라 파일명과 폴더명도 처리하며, 작업 내역은 CSV 보고서로 남깁니다.

이름은 vi의 삭제 명령 `dd`에서 아이디어를 얻었습니다. 식별 정보인 ID를 지운다는 뜻을 담았습니다.

Rust로 만든 단일 실행 파일로, 별도의 DLL 설치나 인터넷 연결 없이 동작합니다. 폐쇄망에서도 사용할 수 있습니다.

## 소스 코드 받기

```sh
git clone https://github.com/maspo1/deid
cd deid
```

## 검출 대상

| 구분 | 항목 |
|---|---|
| 개인정보 | 휴대전화번호(010), 해외 휴대전화번호(+국가번호), 카드번호, 이메일 주소, 주민등록번호, 외국인등록번호 |
| 민감정보 | IP 주소, IP 주소(심층), MAC 주소, 비밀번호, 쿠키, 세션 인증 값, 개인정보·민감정보가 들어 있는 소스코드 주석 |

- **휴대전화번호**는 `010-XXXX-XXXX`만 검사합니다. `+82 10-…`, `+1 (555) …`처럼 국가번호로 시작하는 표기는 **해외 휴대전화번호** 항목입니다(국가번호 표 + 8~15자리).
- **IP 주소**만 켜면 `192.168.0.1`처럼 점으로 쓴 표기만 찾습니다. **IP 주소(심층)**을 켜면 점 대신 다른 기호를 쓴 IP(`192-168-0-1`, `103^234^126^56`)까지 표 검사와 학습 모델로 찾습니다. 심층은 오탐이 늘 수 있어 기본으로 꺼져 있습니다.

사용자 정의 정규식으로 검출 패턴을 추가할 수 있습니다. 확신이 낮은 검출 결과는 보고서에 `검토필요`로 표시합니다.

세션 인증 값은 고정 형식(AWS·GitHub·Slack·JWT·Google OAuth·SendGrid·Hugging Face·Telegram 봇 토큰, Slack·Discord 웹훅 URL, PEM 개인키 등), Cookie·Authorization 헤더, `키 = 값`(로그·설정·JSON) 세 가지로 찾습니다. 세션·쿠키 키는 HTTP 맥락이 있거나 값이 기계가 만든 모양(16자 이상, 영문·숫자 섞임, 높은 엔트로피)일 때만 채택하고, `JSESSIONID`·`connect.sid` 같은 세션 쿠키 이름과 `세션키`·`인증토큰` 같은 한글 키도 인식합니다. 주소(URL)·코드 식(`request.form[...]`)·설정 항목(`session_timeout`, `api_key_header`)은 값으로 보지 않습니다.

소스코드 주석은 안에 위 정보가 들어 있을 때만 주석 전체를 치환합니다. 평범한 설명 주석은 그대로 두고, 문서 주석 기호(`///`, `//!`, `/**`)는 코드가 바뀌지 않도록 치환하지 않습니다.

## 지원 파일

확장자보다 **파일 시그니처(매직 바이트)**를 기준으로 형식을 판별하므로, 확장자를 바꾼 파일도 실제 형식에 맞춰 검사합니다.

| 형식 | 대상 |
|---|---|
| 텍스트·소스코드 | 일반 텍스트, 소스코드와 주석, JSON, XML, HTML 등 |
| Office 문서 | DOCX, XLSX, PPTX |
| 한글 문서 | HWPX |
| PDF | PDF 문서 |
| 압축 파일 | ZIP |
| 이미지 | PNG, JPG, BMP |

문서에 포함된 이미지와 썸네일도 OCR로 검사하고, 검출된 정보가 있는 영역을 흐림 처리합니다. 결과는 원본의 폴더 구조를 유지해 별도 폴더에 저장합니다.

## 검출 방식

### 1. 비트 병렬 패턴 검사

전화번호, 주민등록번호·외국인등록번호, 카드번호, IP 주소의 형식을 하나의 비트 병렬 상태 행렬(Shift-And)로 동시에 검사합니다.

행렬의 칸에는 올 수 있는 숫자만 넣어 둡니다. 예를 들어 주민등록번호 뒷자리 첫 칸은 1~8, 휴대전화 가운데 번호 첫 칸은 1~9만 허용하므로 존재할 수 없는 번호는 검증 단계까지 가지 않습니다.

주민등록번호의 생년월일은 윤년과 월별 일수를 미리 계산한 날짜표로 확인합니다.

### 2. 규칙 기반 검증

IP 주소의 옥텟 범위(0~255), 휴대전화 식별번호, 주민등록번호 검증 숫자, 카드번호 Luhn·발급사 번호(IIN) 검사 등을 적용해 형식만 비슷한 값을 걸러냅니다. Luhn과 IIN은 미리 계산한 표로 조회합니다.

형식마다 구분자가 올 수 있는 자리(예: 주민등록번호는 6자리 뒤, 카드번호는 4·8·12자리 뒤)를 비트로 미리 구운 **구분자 위치 정답 행렬**과도 비교합니다. 구분자가 빠진 표기는 통과하고, `00013027665 14`나 `250117,250118,2502`처럼 엉뚱한 자리에 구분자가 있으면 탈락합니다.

주민등록번호는 보통의 표기(`YYMMDD-NNNNNNN`)가 아니면 치환하되 `검토필요`로 표시합니다. 구분자 없이 붙여 쓴 13자리는 검증 숫자(체크섬)까지 맞아야 합니다. 체크섬은 자리(12)×숫자(10) 가중치 정답 행렬로 한 번에 계산하고, 공식은 성별 숫자로 정합니다(1~4 내국인, 5~8 외국인). 2020년 10월 이후 발급 번호는 뒷자리가 임의라 체크섬이 없으므로, 붙여 쓴 번호의 생년월이 그 이후면 검증할 수 없어 번호로 보지 않습니다(`2507224910019` 같은 날짜형 문서번호 오탐 방지). `-`로 쓴 번호는 날짜·성별만으로 검출합니다. 카드 맥락 없이 붙여 쓴 카드번호 모양 숫자열도 마찬가지입니다.

### 3. 맥락 기반 판별

`192-168-0-1`(IP 주소(심층)을 켰을 때), `010_1234_5678`, `010→1234→5678`처럼 구분자가 바뀌거나 생략된 번호는 내장 GBDT 모델이 주변 맥락을 함께 살펴 판별합니다. 모델이 고른 결과도 위의 규칙과 구분자 위치 정답 행렬을 다시 통과해야 검출됩니다.

점(`.`)을 한 가지 규칙으로 일괄 치환한 IP(`103^234^126^56`, `130-170-164-10`, `105 -> 174 -> 171 -> 43`)는 모델 앞단의 표 검사로 판단합니다. 구분자를 원-핫 인코딩 대신 아스키 코드값 그대로 비교해, 세 구분자의 코드가 모두 같으면(XOR 합 0) 같은 규칙으로 봅니다. 4묶음·0~255·장비 주소 대역을 통과하면 확정합니다. 숫자표의 열 구분자(`,` `|` `/` 공백·탭)로만 이은 것은 표 한 줄과 겹치므로 IP 맥락이 있을 때만 표 검사로 확정하고, 맥락이 없으면 모델이 판단합니다. 모델이 '정보 아님'을 골랐어도 구분자가 한 규칙이면 정보 클래스 확률이 0.46 이상일 때 치환하되 `검토필요`로 표시합니다(전화·IP·카드·주민번호 공통). 다른 해석(월·일, 시각, 절 번호 범위, 파일명·버전)이 있는 것은 모델이 맥락으로 판단합니다. 기호가 섞인 것(`73,202~66-252`, `1 0 0 : 1`)은 하나의 규칙으로 복원할 수 없어 IP로 보지 않습니다(같은 규칙을 따르는 레코드 묶음만 예외). 전화번호의 하이픈을 `+` `/` `|` 공백 등 한 기호로 바꾼 것도 확정합니다.

레코드 구분자(`,` `;` `|` 공백 `[]` 등)로 이어진 묶음은 레코드마다 떼어서 판별합니다. 프로그램으로 변형한 유출(`88^11^25*1,88&11$25*1`)은 레코드마다 같은 규칙을 따르므로 IP로 복원하고, `21.0.88.11.25.1.7`처럼 숫자 덩어리 안에 묻혀 하나의 규칙으로 떼어낼 수 없는 숫자열은 버립니다.

모델은 구분자를 일부러 빼거나 바꾼 표본과, 프로그램 변형 레코드 묶음, 쪽 범위(`28-35, 97-98`)·PDF 좌표·숫자표·값 변화(`31.6→35.8`)·파일명 같은 함정 표본으로 학습합니다. 처음 학습한 뒤에는 새 seed 로 정답·오답 표본을 만들어 모델이 틀린 것만 골라 학습 데이터에 더하고 다시 학습하는 과정을 3번 반복합니다. 학습과 평가는 다음 명령으로 다시 할 수 있습니다.

```sh
cargo run --release --example train_ml   # 학습 (src/rules/ml/*.txt 갱신)
cargo run --release --example eval_ml    # 재빌드 후 평가: 정형 표기·변형 표기·함정·보고된 오답
```

### 4. 이미지 OCR

숫자·영문·기호에 특화된 자체 경량 OCR로 먼저 읽습니다. 인식 확신이 낮은 줄은 Windows 내장 OCR로 다시 확인합니다.

## 사용법

### GUI

`deid.exe`를 실행하거나, 검사할 폴더를 실행 파일 아이콘에 끌어다 놓습니다.

예를 들어 `애플` 폴더를 검사하면 다음 순서로 진행됩니다.

1. `애플_1번` 폴더에 비식별화 결과와 CSV 보고서를 생성합니다.
2. 결과를 검토하고 승인합니다.
3. 재검사를 거쳐 `애플_검사완료` 폴더로 확정합니다.

**검출 결과** 탭에서는 같은 값·같은 정보 종류를 한 행으로 묶어 보여 줍니다(펼치면 파일별로 표시). 오탐은 이렇게 제외합니다.

- 체크를 해제하거나 우클릭 → **제외**: 그 값(같은 값 모두)을 치환하지 않습니다.
- 우클릭 → **이 형식은 제외**: 같은 정보 종류에서 숫자만 다른 값을 모두 제외합니다. 예를 들어 IP로 잡힌 `1 0 0 : 1`을 제외하면 `2 5 5 : 3`도 제외됩니다.
- 제외는 다시 검사할 때 반영됩니다(Windows: 승인할 때, macOS: **제외 반영해 다시 검사**).

### CLI

```text
deid <검사할 폴더> [옵션]
deid --text "검사할 문자열" [--lang 파일명.확장자]
deid --help
```

### CSV 보고서

보고서에는 원본 값, 치환 값, 정보 종류, 파일 경로가 기록됩니다.

```csv
010-1234-5678,***-****-****,휴대전화번호,C:\...\a.log
192.168.0.1,***.***.*.*,IP주소,C:\...\b.pptx
```

## 빌드

Rust stable 하나만 있으면 됩니다. 공통 검사 엔진은 같고, 화면과 OCR만 OS별로 다릅니다.

| OS | 화면 | 명령 | 결과 |
|---|---|---|---|
| Windows 10 이상 (64비트) | Win32 네이티브 | `cargo build --release` | `target/release/deid.exe` |
| macOS (Apple Silicon) | AppKit 네이티브 | `sh assets/macos/make_app.sh` | `target/aarch64-apple-darwin/release/deid.app` |
| Linux 등 | 없음 (CLI만) | `cargo build --release` | `target/release/deid` |

- **Windows**: `build.rs`가 아이콘·매니페스트·버전 정보를 exe에 넣습니다. MSVC 툴체인은 `rc.exe`(Visual Studio Build Tools), GNU 툴체인은 `windres`(MinGW)를 씁니다. `.cargo/config.toml`에서 CRT 정적 링크를 설정하므로 exe 하나만 배포하면 됩니다.
- **macOS**: 앱 번들(아이콘, 번들 ID, 폴더 접근 권한 설명)을 만들고 ad-hoc 서명합니다. 맨 실행파일(`cargo build`)은 아이콘이 없고 다른 폴더 접근이 막힐 수 있으니 앱 번들을 쓰세요.
- **Linux 등**: 화면 없이 CLI로 동작합니다. 인자 없이 실행하면 사용법을 출력합니다.
- 다른 OS에서 Windows 대상으로 교차 빌드하면 리소스 컴파일러가 없을 때 경고만 내고 아이콘·매니페스트 없는 exe를 만듭니다. 배포용 exe는 Windows에서 빌드하세요.
- `examples/train_ocr`, `examples/bench_ocr`는 Windows 기본 글꼴·GDI를 쓰는 Windows 전용 도구입니다. 다른 OS에서는 안내 문구만 출력합니다.

```sh
cargo test --release
```
